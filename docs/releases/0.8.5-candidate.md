# 0.8.5 shadcn compatibility candidate

This unpublished candidate adds a CSS-only theme for upstream shadcn/ui source
installed directly in a web consumer. It adds no new component API or DOM
implementation to the universal package. Native sources and the existing browser
adapter remain unchanged.

`@bubbasfw/ui/shadcn.css` supplies Tailwind4 theme mappings and semantic colors;
`@bubbasfw/ui/shadcn-theme.css` supplies the variables alone. Both derive from
unchanged pinned Studio0.5.0 foundations and are checked during build/prepack.
Standard shadcn link buttons and destructive alerts/menu items select the
canonical link/error foreground inks through scoped semantic variables, including
Dark appearance. Solid destructive buttons keep the red fill and white label.
Native peers become optional at install so a CSS-only React web consumer does not
need native runtimes. Apps using the native/root or RNW entries still install the
peers documented for those entries. The workspace retains its Tailwind3 version;
the widened peer permits Tailwind4 for the CSS-only path.

The Social implementation candidate is the real consuming application. It keeps
upstream shadcn component source, dependencies and APIs in Social, with normal
component installation via its CLI. Auth, providers, stored records and guard
behavior remain Social-owned. No production actions belong to the proof.

Local UI build, types, foundation/font and SSR/browser form results are recorded
by the implementation task. Social separately records its packed input hash,
upstream component installation, local fixture journeys and screenshots. These
are candidate checks, not production deployment or native device acceptance.

Publication requires separate owner approval of the exact reviewed final archive.
Do not repack or replace immutable published0.8.4. After approval, publish the exact
reviewed0.8.5 archive, verify registry bytes, then deliberately update each consumer
through its own release procedure. No automated publication/deploy is added.
