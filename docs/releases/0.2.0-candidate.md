# 0.2.0 candidate

Historical qualification snapshot for the runtime-tested candidate, before public
publication receipts. Both npm 0.2.0 and Pages were subsequently published and
verified. Current receipts and the later README-only publication artifact are in
the [0.2.0 release record](0.2.0.md). The original [0.1.0 release record](0.1.0.md) stays separate.

At this snapshot, the candidate was unpublished and public npm remained `0.1.0`.
The owner approved publishing the package and docs after reviewing the concrete
result; neither publication had yet been verified. A push, merge, build or
document did not publish either automatically.

The candidate expands the package to 32 React Native/NativeWind components,
scoped light/dark/system semantic themes and complete Next/Expo galleries. The
static visual workbench puts actual component previews, state controls and
browser-local Keep/Change feedback first, with simple platform setup and source
examples available below. The selected public host is
`handh-dev.github.io/bubbas-ui`. The subsequent verified deployment is recorded
separately in the release record.

## Web and bundler validation

The packed report passed an isolated Next production build and actual browser
behavior across the 32-component gallery. It covers editing, pointer/keyboard
actions, disabled/loading states, choice keyboard handling, roving focus, Select,
Accordion, Toast, Progress and Pagination. Dialog/Sheet coverage includes focus
wrapping, dismissal, two-trigger restoration, nested scroll locking, SSR
`defaultOpen` and three reopen cycles. Browser page errors were empty.

Expo exported both iOS and Android Hermes bundles from an isolated installed
consumer. These exports establish bundler compatibility; they are separate from
the installed iOS runtime checks below. The packed verifier's
`nativeDeviceRuntime: "not tested"` field describes that verifier's own scope.

Workspace typechecks passed. A separate Next StrictMode development gallery run
passed, including overlays. The final nested-readiness assertion waits for the
expected dialog and focus within it, avoiding a parent-dialog readiness race;
`artifacts/verification/overlay-readiness-scope.json` records a passing three-cycle
`defaultOpen`/nested fixture with zero page errors.

The static docs build and latest browser sweep passed all 35 routes: home,
32 components, foundations and setup. Checks include search, visual controls,
platform disclosures, appearance and feedback persistence, JSON export,
client-navigation resets and 320/390/1440 overflow checks. Two tabs retain separate
feedback; quota-write failure and failed legacy migration preserve feedback for
export. Evidence: `artifacts/verification/docs/report.json`.

## Installed native runtime

`artifacts/native-review/report.json` and `artifacts/native-review/README.md`
record a passing dedicated installed Release harness on an arm64 iPhone 17 /
iOS 27.0 simulator. It used Expo 57.0.31, RN 0.86.3 and the documented
`expo-build-properties@57.0.22` scene-lifecycle opt-in. All 34 installed package
files matched the reviewed tarball before a fresh Expo export; the resulting
Hermes payload was embedded in the proven native Release harness. The app's
embedded bytes matched payload SHA256
`8e92c0021b08104795924d29d686eb391f97b2e2cb78358b51e6a07024a05d6a`.
Identity/method evidence is retained in `final-installed-artifact.json` and
`final-payload.json` in that evidence directory.

All 32 components were selected and mounted natively. Representative checks
covered Button activation; editable and inactive Input; Checkbox toggle, mixed
and disabled states; Switch and RadioGroup; Select commit/reopen/cancel; Tabs and
Accordion; Dialog from both triggers with backdrop/Close dismissal; Sheet; Toast;
Pagination first/last bounds through page 5; and Progress 20%→40%. Light/dark
appearance, corrected native safe-area/status-bar colors and a dark scoped Dialog
were checked after the final gallery-frame refresh. Final captures are
`phone-ios-light.jpg`, `phone-ios-dark.jpg` and `native-dialog-dark.jpg`; field,
chooser, Dialog and Sheet captures from the same package before that frame-only
correction remain in the same directory.

This proves the observed simulator runtime and representative behaviors, not
every prop/variant combination. No physical device, Android runtime,
tablet/landscape, VoiceOver or external-keyboard native qualification was
performed. The initial Expo Go 57.0.9 attempt failed before UI mounting because
its ExpoAsset native registry was unavailable; the successful proof uses the
dedicated installed harness. The Expo example uses the documented system-font
fallback; docs host Montserrat separately.

Cleanup is complete: the owned simulator was deleted, unrelated simulator states
were unchanged, temporary log helpers stopped, and both build-space leases were
released. Heavy fixture, DerivedData and ExpoGo app resources were moved to
recoverable Trash; screenshots, reports, hashes and fixture configuration records
were retained. No disk-space reclamation is claimed.
