# 0.7.0 mobile marketing refinement candidate

Unpublished design candidate for shared UI, Studio's isolated review catalog and
the main website. Exact owner review is required before npm publication or app
release. Approved 0.6.1 remains the public release at preparation time. Native
apps, Bulk, Social/print and existing operational surfaces remain outside adoption.
The owner separately requested a narrow Core-backed promotional announcement
authoring flow; the reusable editor lives here, while HQ/Core own that workflow.

## Shared behavior

- Existing marketing section props remain; callers supply facts, routes and
  artwork. The website omits HeroSection's optional description. On phones the
  repeated hero logo is hidden while the H1 and caller mascot remain. A readable
  gold honor badge carries the caller's exact eyebrow.
- Marketing actions have intrinsic widths, >=48px phone targets, one-line labels,
  red/blue glow and real hover/focus/pressed/inactive states. The 0.6.1 object,
  array, callback, RTL, form and NativeWind style forwarding remains intact.
- Announcement is static, single-line and fitted, with safe white/yellow text
  sections and optional caller-owned concise phone copy. The controlled shared
  AnnouncementEditor previews the real banner, formats selected words, preserves
  Unicode edits and warns about unreadably long phone text. Core/app own data/save.
- Navy ticker endcaps carry only white stars. The text lane keeps white/red rails.
  Motion keeps moving on hover. A persistent shared Motion switch in navigation
  and footer stops ticker, badge/honor effects, promotion bursts and decorative
  action movement; standalone catalog examples expose
  the same exported MarketingMotionControl. The choice persists across ordinary
  page loads with a caught storage/in-memory fallback in opaque Studio frames.
  Reduced motion starts static and disables that switch while the OS preference
  is active. The dark footer uses a separated white focus outline.
- Promotion action stays aligned to its copy region. Short side bursts remain
  bounded, decorative and noninteractive on hover/focus/touch. Gold product badges
  have a metallic gold treatment, reflective pass and continuous staggered gold-only
  four-point twinkles; social description uses pale warm
  gold #FFFAE8 on original blue (4.61:1 normal-text contrast).
- Phone campaign badges form one nonshrinking, scrollable row with an explicit
  keyboard focus target and white focus ring. Footer places brand
  first, two link columns next, then season content; no extra white logo well is
  painted. Original asset bytes and outline geometry remain caller-owned.
- Product detail contains artwork within min(60vw,280px), uses 48px phone thumbnails
  and closer spacing, retaining all names/facts/gallery/video/actions. Shared web
  Dialog uses a restrained 200ms opacity/10px entry and exit, maintaining its portal,
  focus trap and scroll lock through exit and returning focus after unmount.

## October 23 follow-up directions

The owner requested twelve further corrections. This candidate preserves the
previous candidate5 archive while refining the same reusable system: compact
same-row hero actions, real metallic gold, continuous gold-only twinkles, longword
wrapping, wider responsive grids, transparent action sections, half-width star
caps, shared promotion sparkles, navigation hover highlights, all six supplied
social accounts, caller-supplied approved rocket category artwork and a static

[Magic UI Sparkles Text](https://magicui.design/docs/components/sparkles-text) is

palette is imported. The four new social vectors retain Simple Icons 16.35.0 CC0
provenance and committed source/raster hashes. No brand font/art binary is bundled.

## Candidate 7 paint correction

Candidate6 is superseded: an actual HQ isolated-document check found that the
RN Web atomic sheet could override a yellow segment's inline color class with
white. Safe stored segments were correct, but paint was wrong. The shared yellow
class now owns gold foreground and navy backing in either stylesheet order, and
default segments alone receive the white utility. Native retains its explicit
gold/navy style. Actual browser checks cover opaque classic-script hydration and
no-JavaScript SSR in both atomic-sheet orders with loaded Montserrat, asserting
computed white/default, gold/highlight and navy/backing colors.

Candidate7 uses the same normal `npm pack --json --ignore-scripts` path as full
package verification. Older archives remain preserved; none is replaced or
published. Fresh exact source/package/consumer checks and owner review still apply.

## Candidate 8 inline spacing correction

Candidate7 is superseded: the static announcement used flex display for its text
container and fit measurement, which suppressed meaningful whitespace at the
edges of separately highlighted words. The shared banner now uses ordinary
block/inline text flow for visible and measured copy while retaining single-line
fitting. Actual browser DOM Range checks assert positive whitespace advance at
plain-to-yellow and yellow-to-plain boundaries, punctuation and two highlighted
runs in desktop and phone copy, across opaque classic hydration and no-JavaScript
SSR in both stylesheet orders. Existing gold/white/navy computed-paint checks stay.
